# P2 改善使用體驗 Design Spec

**日期：** 2026-08-05  
**狀態：** 待使用者審閱  
**範圍：** 第一階段三個 tab 的局部 UX 改善  

## 1. 目標

讓使用者在不改變月份資料口徑與 tab 邊界的前提下，更快完成三件事：

1. 從「推薦意願專區」的 Key Driver 圖表辨認優先改善項目。
2. 從「出團長評回饋」快速定位情緒、目的地、領隊與關鍵字相關的長評。
3. 從「綜合意見」先看策略結論，再按需展開證據與行動建議。

本階段只改展示層與互動層，不重算既有業務指標，不把 UX 欄位或 formatter 寫入月份 JSON。

## 2. 使用者與工作情境

主要使用者是每月更新問卷資料後，快速檢查營運問題、產品機會與服務品質的業務分析使用者。典型情境是：

- 在同一月份內往返多個 tab，比較數據與文字洞察。
- 先找異常或優先改善項，再閱讀支撐該判斷的長評。
- 需要知道數字的統計口徑，避免將樣本數、長評數與多選提及數混用。
- 需要保留原始長評的可追溯資訊，包括團號、目的地、領隊、評論類型與評論內容。

## 3. 設計原則

### 3.1 Tab 邊界清楚

正式實作仍維持既有 tab：

- `nps_zone`：推薦意願專區
- `feedback_analysis`：出團長評回饋
- `analysis`：綜合意見

三個 tab 不合併成一個總頁，也不把其它 tab 的資料搬入上述頁面。

### 3.2 Canonical artifact first

月份 JSON 是唯一業務資料來源。前端只能讀取與呈現資料，不能在瀏覽器端回寫 JSON、修改月份資料或暗中補造數字。

### 3.3 可計算欄位與展示欄位分離

KPI、count、百分比、情緒統計與門市／長評總 N 維持現有驗證腳本的口徑。UX 改善只增加呈現方式、篩選狀態與可讀性，不改變計算規則。

### 3.4 重要資訊不隱藏

折疊只用於策略長文，不用於團號或評論本身。長評卡片即使在篩選後，仍須顯示團號；若原始資料沒有團號，明確顯示「未提供」，不能空白到讓人誤以為資料遺失。

## 4. 方案比較與選擇

### 方案 A：只調整 CSS 與文字排版

優點是改動最少；缺點是無法解決 Key Driver 標籤重疊，也無法降低長評搜尋成本。只適合短期修補，不足以支援本次 P2 目標。

### 方案 B：保留現有資料與 DOM contract，增加局部互動層（採用）

保留現有 `index.html`、`app.js`、canvas id、tab id 與月份資料結構，只在既有 render/filter 邏輯上加入：

- Key Driver 的圖表／排名分離與點選同步。
- 長評的搜尋欄、篩選結果狀態與團號固定呈現。
- 綜合意見的 section/card 展開收合。

這個方案符合目前 Vanilla JS + Chart.js 架構，改動可逐 tab 驗證，回歸風險最低。

### 方案 C：引入新的 UI framework 或元件庫

可提供更完整的元件系統，但會增加 bundle、建置流程與月份 dashboard 的回歸面，與現有可攜式單頁架構不相稱。本階段不採用。

## 5. 功能設計

### 5.1 推薦意願專區：Key Driver 可讀性

**現況問題：** 九個服務項目集中在散點圖附近，標籤互相遮蔽，難以辨認。

**設計：**

- 散點圖保留作為整體矩陣視覺化，不在每個點旁放完整長標籤。
- 圖表旁或下方增加可掃描的排名列表，列出：服務項目、影響力、平均滿意度、矩陣區域。
- 點選排名列時，同步 highlight 對應散點，並顯示一個短說明區：數值、區域、產品行動。
- 點選散點時反向 highlight 排名列。
- 使用現有 Key Driver 數據，不在 UI 重新計算相關性或象限。
- 小螢幕改為上下排列：先圖表，再排名列表；不以縮小字體硬塞進單一橫排。

**驗收：** 九個項目全部可辨認；至少一個優先改善項與一個核心優勢項可透過點選取得一致的數值與說明。

### 5.2 出團長評回饋：篩選、搜尋與可追溯性

**現況問題：** 長評數量增加後，只靠三個 select 逐項查看成本高；團號是重要追溯欄位，不能因卡片改版而遺失。

**設計：**

- 保留現有情緒、目的地、領隊篩選器。
- 增加關鍵字搜尋，搜尋範圍為目的地、領隊、團號與評論內容。
- 篩選區顯示目前結果數與總長評數，例如「顯示 8 / 40」。
- 每張長評卡片固定呈現：
  - 評論類型
  - 目的地
  - 領隊
  - 團號
  - 完整評論內容
- 團號來源使用 `rawFeedbacks[].tourNo`；缺少時顯示「團號：未提供」。
- 保留現有情緒佔比統計，但統計基於篩選後結果，並清楚標示 `Total: N 則`。
- 無結果時顯示可理解的空狀態，不能留下舊卡片。
- 篩選器值在月份切換後重新依該月份資料生成，避免殘留上一月份的領隊或目的地。

**驗收：** 搜尋一個團號只返回相符長評；清除搜尋後恢復原集合；情緒統計與結果數一致；長評卡片仍顯示團號。

### 5.3 綜合意見：由摘要到行動

**現況問題：** 戰略內容長，使用者需要先抓到主結論，再決定是否讀完整證據。

**設計：**

- 保留三大既有戰略區塊與「綜合建議」區塊。
- 每個戰略區塊的子項目呈現「標題 + 一句摘要」；詳細內容以可展開區域承載。
- 展開內容保留原有資料與建議，不改寫數字。
- 預設只開啟第一個高優先營運痛點，其餘收合；使用者可自行展開。
- 展開／收合不觸發資料重載，不影響其它 tab 的狀態。
- 行動建議使用明確的「問題／證據／建議行動」順序，避免一整段文字無法掃描。

**驗收：** 初次進入可在首屏看到三個區塊標題與摘要；展開後可讀到完整內容；切換 tab 再返回不出現重複卡片。

## 6. 技術邊界與資料流

### 6.1 預計修改責任

| 檔案 | 責任 | 本階段變更 |
|---|---|---|
| `index.html` | tab shell、既有容器與樣式 | 只調整三個 tab 的局部 markup / class / filter control，保留所有 contract id |
| `app.js` | render、Chart.js、互動與篩選 | 增加 Key Driver selection、長評搜尋／狀態、策略展開所需的 UI 邏輯 |
| `js/*.js` | 共用 helper | 只有在既有 helper 能直接承擔且可降低重複時才修改 |
| `data/YYYYMM.json` | 月份純資料 | 不因 P2 UX 改動；僅讀取既有 `tourNo` 等欄位 |
| `scripts/*` | 驗證與 Hermes | 不改既有資料口徑；必要時補靜態 UX contract 測試 |

### 6.2 不變更項目

- `data/months.json` 與任何月份 JSON 的業務數字。
- `globalMonthSelector`、tab ids、canvas ids、`printReport`、`PRINT_SECTION_MANIFEST`。
- NPS、Key Driver、長評情緒 count、門市總 N 等計算口徑。
- 其它 tab 的內容與資料。
- Obsidian／Git 的正式收尾流程；實作完成後仍需 Hermes read-only 驗收與 Obsidian 回填。

### 6.3 長評資料契約

前端讀取 `DataStore.rawFeedbacks`。每筆至少支援：

```text
dest: string
leader: string
tourNo: string | missing
type: positive | suggestion | negative
content: string
```

UI 不得因 `tourNo` 缺失而移除整筆長評，也不得從評論內容自行抽取後覆蓋 canonical `tourNo`。

## 7. 錯誤與空狀態

- 月份資料載入失敗：沿用現有 loading/error overlay，不新增靜默 fallback 數字。
- 欄位缺失：顯示 `未提供` 或空狀態文字，保留其它可用欄位。
- Key Driver 沒有資料：顯示「此月份沒有可用驅動因素資料」，不畫空白假圖。
- 長評篩選無結果：顯示「沒有符合條件的留言記錄」，並保留清除篩選的入口。
- 策略內容缺失：顯示區塊標題與「此月份未提供策略內容」，不借用其它月份文字。

## 8. 驗證策略

### 靜態與資料驗證

```sh
python3 scripts/validate_dashboard.py
python3 scripts/check_month_consistency.py --all --strict-warnings
python3 scripts/check_print_report_static.py
python3 scripts/check_screen_layout_static.py
node --check app.js
```

### 功能驗證

在 HTTP server 下至少驗證：

1. `nps_zone`：圖表與排名列都顯示；點選雙向同步；手機寬度不重疊。
2. `feedback_analysis`：情緒／目的地／領隊／關鍵字篩選；結果 N；團號顯示；無結果空狀態；月份切換後選項重建。
3. `analysis`：預設摘要可見；展開／收合；切換 tab 後無重複內容。
4. PDF：三個 tab 仍能依 `PRINT_SECTION_MANIFEST` 建立列印頁，長評列印內容包含團號。
5. 4 月、5 月、6 月、7 月月份切換不出現跨月文字或舊篩選選項殘留。

### 回歸邊界

每次只修改一個 tab 的 production 行為；完成一個 tab 後先跑該 tab 的功能驗證，再進行跨 tab／完整 Hermes 驗收。不得在同一個 commit 混入其它 tab 的內容改動。

## 9. 分階段交付

1. **P2-1 Key Driver 可讀性**：圖表與排名分離、點選 highlight、responsive layout。
2. **P2-2 長評可追溯篩選**：關鍵字搜尋、結果狀態、團號固定顯示、篩選後情緒統計。
3. **P2-3 綜合意見摘要互動**：策略摘要、展開／收合、內容結構化。
4. **P2-4 整體驗收**：完整 validation、HTTP、screen／print、Hermes、Obsidian 回填。

每一階段都應可獨立 review、驗證與回退。

## 10. 成功標準

- 使用者不需要放大頁面，即可辨認 Key Driver 的九個服務項目。
- 使用者可在三個操作內由長評總表定位到指定團號或關鍵字。
- 長評的團號在畫面與 PDF 中都保留；缺失時有明確提示。
- 綜合意見首屏能先看結論，詳細證據不被刪除。
- 月份資料、計算口徑、其它 tab 與既有 print／Hermes contract 不回歸。
